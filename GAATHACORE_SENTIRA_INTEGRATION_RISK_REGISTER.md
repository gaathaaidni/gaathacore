# Sentira Integration Risk Register — Phase 21

**Scope:** local static review of the imported Sentira source and Phase 12–20A
reports. This is not a production-readiness verdict and contains no live media
claims.

| Priority | Finding | Affected component | Repository evidence | Potential impact | Recommended next action | Runtime validation required |
| --- | --- | --- | --- | --- | --- | --- |
| High | The Stream Gateway's single internal bearer token authorizes retrieval of all organizations' credential-free camera projections. | API internal camera endpoints; Stream Gateway discovery | The protected internal endpoints return all camera IDs, organization/site IDs, and stream URLs to any holder of `STREAM_GATEWAY_INTERNAL_TOKEN`. | Compromise of the gateway service credential exposes cross-tenant stream metadata and permits its holder to request the global projection. | Design a least-privilege service identity/projection contract before production hardening; do not add caller-supplied tenant headers. | Yes, after design and implementation. |
| High | Connector registration tokens are hashed but have no repository-evidenced expiry, rotation, revocation, replay detection, or rate limit. | Camera onboarding and connector endpoints | Connector records retain a token hash; heartbeat and discovery trust a matching bearer token. | A stolen long-lived connector token could continue to authenticate connector actions. | Define connector lifecycle, expiry, rotation/revocation, and abuse controls with focused API and connector tests. | Yes. |
| Medium | Playback JWTs are reusable until their 60-second expiry; `jti` is issued but no replay store is present. | API StreamAuthorizationService; Stream Gateway | Tokens include `jti`, but the static gateway callback only verifies signature/claims/current camera state. | A copied token can be replayed during its short validity period. | Decide whether short validity is acceptable or add a bounded replay/revocation mechanism in a dedicated authorization phase. | Yes. |
| Medium | Publication service token is conveyed in the RTSP target query string and therefore appears in FFmpeg process arguments. | CameraStreamManager/MediaMTX publication | The publication command appends `?token=...` to the RTSP target. | Local users/process inspection or diagnostics can expose the publication credential. | Use process isolation and strict host access now; assess a MediaMTX-supported non-command-line publication credential transport before production. | Yes. |
| Medium | Camera reconciliation is periodic rather than instantaneous. | CameraStreamManager | Discovery is scheduled with `CAMERA_REFRESH_SECONDS` (five seconds by default). | A disabled, deleted, reassigned, or source-updated camera can continue publication until the next successful reconciliation; already-established HLS sessions are not revoked by this mechanism. | Retain this explicit delay in operator documentation and test it live; do not claim active-session revocation. | Yes. |
| Low | Direct stream URLs are deliberately supplied to the Stream Gateway, although public API projections redact them. | Internal camera projection | Public projections remove `streamUrl`, username, and encrypted password; the internal projection retains the stream URL. | Gateway compromise exposes stream locations, but not camera password fields. | Preserve credential-free projection tests and reduce the broad shared-token boundary as above. | No for static contract; yes for service-boundary validation. |
| Environment blocked | Two simultaneous manager-produced streams, MediaMTX callback HTTP results, HLS resources, lifecycle behavior, process cleanup, browser playback, and WHEP have not been observed in this workspace. | Disposable local media validation | Docker-compatible runtime, FFmpeg, MediaMTX, and service dependencies are unavailable. | Runtime authorization/lifecycle regressions could remain undetected. | Provision the existing disposable Phase 20A Compose environment and execute its two-tenant live gate without production resources. | Yes. |
| Environment blocked | API Jest/build and browser validation cannot run because the dependency tree is unavailable. | Sentira API and web | `jest`, Next, React, and related dependencies are unavailable; package installation is blocked by the configured proxy. | API/frontend regressions outside static review remain untested. | Restore dependency access in a disposable development environment, then run focused API and frontend checks. | Yes. |

## Scope note

No Critical finding is assigned from this static review. A Critical rating would
require evidence of an exploitable unauthenticated cross-tenant path or a live
production impact; neither was tested or claimed here.
